## 1. Strateji

### Neden Paralel?

MASTER_PLAN.md'deki kalan işler **bağımsız kategorilere** ayrılabiliyor. Her kategori kendi dosya kümesinde çalıştığı için çakışma riski düşük:

| Kanal | Kapsam | Dosya Çakışması | Süre |
|-------|--------|-----------------|------|
| **A** | Performans & Veri Katmanı | `src/hooks/db/`, `src/lib/` | ~4 saat |
| **B** | Sayfa Refactor (P-series) | `src/pages/` (her sayfa ayrı) | ~12 saat |
| **C** | Kod Kalitesi & Test | `src/agents/`, `src/**/*.test.ts` | ~6 saat |

### Paralellik Stratejisi

```
Zaman:  |--- H1 ---||--- H2 ---||--- H3 ---||--- H4 ---|
Kanal A: ████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
Kanal B: ████████████████████████████████████████████████
Kanal C: ░░░░░████████████████████░░░░░░░░░░░░░░░░░░░░░░
         ↑H1 başı  ↑H1 sonu    ↑H2 sonu     ↑H4 sonu
         (A1-A4)   (A5+B1-2+C1)             (tümü)
```

- **H1 (Saat 0-1):** Kanal A başlar (A1-A4) → Kanal C bekle (bağımlılık yok, test altyapısı lazım)
- **H2 (Saat 1-2):** Kanal B + Kanal C paralel başlar
- **H3 (Saat 2-4):** Tüm kanallar paralel devam eder
- **H4 (Saat 4+):** Doğrulama + Merge

### Commit Stratejisi

Her kanal kendi branch'inde geliştirilir, H3 sonunda `dev`'e merge:

```
dev ←─ Kanal A (feat/perf-data)
     ←─ Kanal B (refactor/pages)
     ←─ Kanal C (chore/test-quality)
```

## 3. Kanal A — Performans & Veri Katmanı (Detay)

### A1: F4 — localStorage.setItem → async batch write

**Mevcut Durum:**
```typescript
// core.ts
localStorage.setItem(STORAGE_KEY, JSON.stringify(nextDB)); // Senkron, büyük DB'de jank
```

**Hedef:**
```typescript
// Batch queue ile async yazma
const writeQueue = new BatchQueue<DB>({
  flushInterval: 100,   // 100ms'de bir flush
  maxBatchSize: 1,      // Son state'i yaz
  writer: (db) => {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(db));
    // Sonra IndexedDB + Firebase
  }
});
```

**Değişen Dosyalar:**
- `src/hooks/db/core.ts` — save pipeline'ı batch queue'ya yönlendir
- `src/hooks/db/sync.ts` — IndexedDB/Firebase yazma da batch'e dahil edilebilir
- `src/lib/batchQueue.ts` — YENİ: Generic batch queue utility

**Test:**
- BatchQueue unit test: 3 farklı flush senaryosu
- core.ts entegrasyon testi: save çağrısı → eventual write

### A2: F5 — Anomali taraması async + Web Worker

**Mevcut Durum:**
```typescript
// anomalyEngine.ts — senkron, CPU-bloking, ~500ms
function scanAll(db: DB): Anomaly[] {
  // 500ms boyunca main thread'i bloklar
}
```

**Hedef:**
```typescript
// Async + chunked processing
async function scanAllAsync(db: DB, onProgress?: (pct: number) => void): Promise<Anomaly[]> {
  const chunks = chunkProducts(db.products, 50);  // 50'şerli gruplar
  let results: Anomaly[] = [];
  for (const chunk of chunks) {
    await yieldToMain();  // requestIdleCallback veya setTimeout(0)
    results.push(...scanChunk(chunk, db));
    onProgress?.(results.length / totalExpected);
  }
  return results;
}
```

**Alternatif:** Web Worker — daha karmaşık ama gerçek paralellik

**Değişen Dosyalar:**
- `src/lib/anomalyEngine.ts` — scanAll → scanAllAsync
- `src/pages/AnomaliOneri.tsx` — progress bar ekle

### A3: C5 — localStorage 5MB limit monitörü

**Mevcut Durum:**
```typescript
// dataIntegrityChecker.ts — sadece hata anında uyarır
```

**Hedef:**
```typescript
// Proaktif monitör — %80 eşikte uyar
function monitorStorageUsage(): StorageStatus {
  const used = new Blob([localStorage.getItem(STORAGE_KEY) || '']).size;
  const limit = 5 * 1024 * 1024; // 5MB
  return {
    used,
    limit,
    percent: (used / limit) * 100,
    warning: used > limit * 0.8,
    critical: used > limit * 0.95,
  };
}
```

### A4 + A5: C7 — excel-merge.ts böl + F6 Levenshtein optimizasyonu

**Mevcut Durum:** `excel-merge.ts` — 742 satır, tek dosyada 4 sorumluluk

**Hedef:**
```
src/lib/excel-merge/
├── index.ts           # Ana orchestrator (~40 satır)
├── mergeEngine.ts     # Birleştirme mantığı (~200 satır)
├── matcher.ts         # Levenshtein + fuzzy match (~150 satır)
├── parser.ts          # Excel parse/format (~150 satır)
└── types.ts           # Tipler (~50 satır)
```

**F6 Optimizasyonu:** Levenshtein full DP → optimizasyon:
```typescript
// Mevcut: O(m*n) memory + time
// Hedef: O(min(m,n)) memory + early termination
function optimizedLevenshtein(a: string, b: string, maxDistance: number): number {
  if (Math.abs(a.length - b.length) > maxDistance) return maxDistance + 1;
  // Tek sıra DP (O(min(m,n)) memory)
  // distance > maxDistance → erken çıkış
}
```
